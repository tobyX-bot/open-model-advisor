# Quiet Strata

Quiet Strata treats information as material: facts settle into measured layers, uncertainty interrupts the section, and human judgment completes the specimen. Space is disciplined and asymmetric, with one dense working plane held inside a field of true white. The composition should feel meticulously calibrated, as if every baseline, divider, and interval has been adjusted over countless passes by a master instrument designer.

Color is structural rather than atmospheric. Morandi blue establishes the raw-sample chamber; white and blue-tinted neutrals separate verified work from unresolved evidence; a small mineral amber signals review without turning the interface into an alarm panel. There are no gradients, decorative textures, or ambient effects. Material depth comes from adjacency, hairline divisions, and one carefully crafted glass lens reserved for active inspection.

Scale follows evidentiary importance. Exact model strings carry quiet monospace authority, while interface labels remain in a precise SF/system sans hierarchy. A large recommendation name is earned only after review and application. Words are concise and functional; the visual sequence of raw sample, extracted strata, verified setup, and fit guidance carries the explanation. Craft is visible in the repeated alignment of source snippets, confidence marks, controls, and status language.

Rhythm comes from layers, not cards. Evidence rows accumulate like a core sample, each with a stable depth marker, status, exact value, and source. The shovel is used as the working scan control and as a restrained identifying mark, never as illustration. Motion is brief and purposeful: the lens advances through input, extract, verify, and match, while the rest of the interface remains materially still. Reduced-motion behavior preserves every state change without travel.

The finished surface should reward close inspection. Confidence is never encoded by color alone; conflict remains visible after correction as part of the sample's history; manual edits live beside detected evidence rather than behind another page. Every mobile wrap, Mandarin line, focus ring, and control dimension receives the same painstaking attention as the desktop composition. The result should look labored over with care and deep product expertise, not decorated after the workflow was decided.

## Interaction System

- The raw setup stays visible while scanning, reviewing, correcting, and applying.
- The four-stage lens advances through **Input -> Extract -> Verify -> Match** in short deterministic steps.
- Extracted hardware forms a layered core sample. Selecting a layer opens its exact source evidence in the active glass inspector.
- A visible VRAM conflict requires a source choice or manual value before the setup can be applied.
- The exact hardware editor expands in place and exposes OS, device, CPU, RAM, GPU, VRAM, and free storage.
- Applying the reviewed setup unlocks a concrete **Try first** recommendation. Task and deployment changes update the recommendation without hiding the reviewed hardware.
- English and Mandarin switch all important visible interface, evidence, issue, control, and recommendation copy.

## Material, Color, And Type

- **Raw sample:** solid deep Morandi blue (`#314954`) with white type.
- **Working field:** true white (`#ffffff`) and cool blue-gray (`#eef3f5`) opaque surfaces.
- **Primary ink:** cool near-black (`#17242a`); secondary copy remains dark enough for WCAG AA.
- **Review:** mineral amber with an icon and explicit text; verified state uses blue-green plus a check label.
- **Glass:** used only for the scanner tray and active evidence inspector, with a fallback opaque blue surface.
- **Type:** SF/system sans for hierarchy; restrained SF Mono/system monospace only for exact hardware and source snippets.
- **Shape:** 4-10px radii, 1px separators, stable control heights, and no nested-card framing.

## Intentional Departures From V2

1. Replaces the left scanner / center rail / right findings split with one continuous specimen table.
2. Makes evidence layers the central navigation and keeps their source snippets inspectable in place.
3. Treats manual correction as a first-class continuation of review, not a detached details band.
4. Compresses the progress rail into a functional scanner lens directly attached to the raw sample.
5. Keeps the recommendation ledger visible beside evidence, so cause and result can be compared without scrolling between sections.
6. Removes repeated numbered eyebrows, decorative glass, dark-default results, and generic result-card stacks.
7. Preserves conflict history after resolution to communicate that a value was reviewed, not confidently auto-detected.

## User Tests Before Production

1. Can people explain which values were detected, which were inferred, and which were manually resolved before they apply the setup?
2. Do users notice the blocking conflict and understand that selecting a source is different from merely dismissing a warning?
3. Does the core-sample metaphor improve scan/review comprehension in English and Mandarin, or does it add vocabulary without functional value?
4. On 390px screens, can users move from paste to issue resolution to exact edit to recommendation without losing context or encountering excessive vertical fatigue?
5. Do users understand that the hosted option is secondary and that local parsing does not imply local model execution is always practical?
6. Can keyboard and assistive-technology users follow stage updates, evidence selection, issue resolution, application, and recommendation changes in a coherent order?
